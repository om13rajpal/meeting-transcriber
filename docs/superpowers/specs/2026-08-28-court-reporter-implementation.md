# Meeting Transcriber · Court Reporter implementation spec

> Generated by moodforge · 2026-08-28 · for court-reporter v1 · Step 6 of 6

---

## Goal

Ship the Court Reporter design system into the real Next.js app: replace the placeholder oklch theme in `app/globals.css` with the locked token set, wire the three real typefaces, correct the shadcn primitives that fight the brand, and rebuild the Landing, Dashboard, MeetingDetail and Auth screens to match the approved Round 5 mockups, with the motion system applied exactly as locked in Round 4.

## Scope

**In:**

- The full token merge into `app/globals.css` (shadcn slot map plus the `--cr-*` brand primitives plus the reduced-motion block).
- Real font loading for Geist, Big Shoulders Display and IBM Plex Mono via `next/font`.
- Corrections to `components/ui/button.jsx` (destructive variant, press feedback, `transition: all`, focus ring width).
- Five missing shadcn components installed and wired.
- A new signed-out Landing surface at `/`, which does not exist in the codebase today.
- Rebuild of `app/Dashboard.js`, `app/meeting/[id]/MeetingDetail.js`, `app/login/`, `app/signup/`, `app/forgot-password/`, `app/reset-password/[token]/` chrome to the Round 5 mockups.
- Brand-consistent pass over `app/share/[token]/` (it is a marketing surface per the brand kit's surface split).
- GSAP motion for the marketing surfaces, CSS transitions for the product surfaces.
- Accessibility pass against the brand kit's WCAG matrix, keyboard navigation, and `prefers-reduced-motion`.

**Out:**

- Any change to Server Actions, Mongoose models, the backend service, the upload token flow, notifications, or cost tracking. This is a presentation-layer change. If a screen needs data the actions do not already return, stop and raise it rather than reshaping an action.
- TypeScript. `docs/design/brand-kit/tokens.ts` is a design-system artifact for Figma and Style Dictionary. It must never be imported from `app/` or `backend/`. See CLAUDE.md, "Conventions".
- A real product name. The wordmark stays the placeholder `MEETING.TXT`. See Open item 5.
- Any second theme layer, light-mode toggle, or `prefers-color-scheme` branch. The app is always dark, `className="dark"` on `<html>` in `app/layout.js`.
- Re-running `npx shadcn@latest apply <preset>`. That would overwrite the Court Reporter values in `app/globals.css` with the stock `nova` neutral theme.
- Rewriting `buildSnippet()`'s cut behaviour, unless the engineer explicitly opts in. See Open item 6.

## Conventions this spec inherits

From `CLAUDE.md`, non-negotiable and unchanged by this work:

- JavaScript, not TypeScript. No `.ts` or `.tsx` in `app/` or `components/`.
- shadcn here is **Base UI, not Radix**. Use `render={<Component />}`, never `asChild`. Pass `nativeButton={false}` when a `Button` renders as an anchor. `DropdownMenuLabel` must sit inside a `DropdownMenuGroup`.
- Never build DOM from user or API data with `dangerouslySetInnerHTML`. `highlightText()` in `lib/utils.js` returns React elements for exactly this reason.
- Any locale-sensitive formatting in a Client Component pins `'en-US'` and normalises space variants. See `formatDate` in `app/Dashboard.js`.
- Map Mongoose documents to plain objects before they cross the Server-to-Client boundary.
- Comments explain why, not what.

And one style rule from the user, applied to every file this spec produces:

- **No em dashes.** Not in prose, not in JSX copy, not in code comments, not in commit messages. Use commas, periods, or two sentences. A PR check for this is in the Risks table.

## Tasks

### 1. Merge the tokens into `app/globals.css`

Court Reporter is applied by **replacing values in the existing file**, not by adding a second theme layer. Variable names are identical, only the values move.

1. Replace the whole `.dark { ... }` block (currently `app/globals.css` lines 39 to 66) with the `.dark` block from `docs/design/brand-kit/tokens.css` section 9.
2. Replace the colour variables inside the existing `:root { ... }` block (lines 7 to 33) with the `:root` block from the bottom of `tokens.css`. **Keep `--radius: 0.625rem`.** It is not part of this redesign and `tokens.css` does not restate it. The app is always dark so `:root` is never active today, but filling it in stops the light branch from lying about the brand, and gives the paper side of Court Reporter (the transcript card, print, a future PDF export) real values to reach for.
3. Append the entire `--cr-*` primitive block (`tokens.css` sections 1 through 10) inside `:root`. These are the values that have no shadcn slot: the display font stack, the eleven-step type ladder, the stroke scale, the four rule tones, the motion tokens, the status tints, the two shadows.
4. Append the `@media (prefers-reduced-motion: reduce)` block from the bottom of `tokens.css` verbatim. It flattens every `--cr-dur-*` to 1ms, drops the staggers to 0ms, and sets `--cr-press-scale` to 1.
5. Add the four motion-shape properties locked in Round 4, which `tokens.css` does not carry because they were derived in the animation gallery. Put them in `:root` alongside the `--cr-*` block, and flatten them in the same reduced-motion block:

```css
/* Motion SHAPE, the part reduced motion flattens. Every entrance writes its
   travel and scale through these instead of literals, so reduced motion can
   remove the movement without stranding anything that is positioned by a
   transform (a centred modal, a pinned drawer). Locked in Round 4. */
--m-y:         8px;
--m-y-lg:     12px;
--m-scale:    0.95;
--m-scale-tip: 0.97;
--m-blur:      2px;
--cr-stagger-char: calc(var(--cr-stagger-row) / 2);  /* 25ms, derived, not a new token */
```

```css
@media (prefers-reduced-motion: reduce) {
  :root {
    --m-y: 0px; --m-y-lg: 0px; --m-scale: 1; --m-scale-tip: 1; --m-blur: 0px;
  }
}
```

**Naming trap, read before you type.** shadcn's `--accent` is **not** the brand accent. In shadcn it is the subtle hover surface behind menu items and rows. Setting it to stamp red turns every dropdown hover into a red block. The brand red lands on `--primary` and `--ring`. `tokens.css` already maps `--accent` to `#1A1A1D`.

**Second trap.** Never use `text-primary` on dark. `--primary` is `#B8202D`, a surface colour, and measures 3.02:1 as text on the canvas. Red text uses `--cr-red-text` (`#EC4B57`), which is also what `--destructive` is set to.

### 2. Wire the fonts (resolves Open item 1)

Install `geist@1.7.2`, then rewrite `app/layout.js`:

```js
import './globals.css';
import { GeistSans } from 'geist/font/sans';
import { Big_Shoulders_Display, IBM_Plex_Mono } from 'next/font/google';
import { Toaster } from '@/components/ui/sonner';

// Three faces, three CSS variables, all self-hosted by next/font so there is
// no CDN request and no layout shift. Big Shoulders is a condensed display
// face and reflows the page measurably when it lands, which is why the
// marketing surfaces call ScrollTrigger.refresh() on document.fonts.ready.
const display = Big_Shoulders_Display({
  subsets: ['latin'],
  weight: ['800', '900'],
  variable: '--font-big-shoulders',
  display: 'swap'
});

const mono = IBM_Plex_Mono({
  subsets: ['latin'],
  weight: ['400', '500', '600'],
  variable: '--font-ibm-plex-mono',
  display: 'swap'
});

export const metadata = {
  title: 'Meeting Transcriber',
  description: 'Private, self-hosted meeting transcription with Deepgram.'
};

export default function RootLayout({ children }) {
  return (
    <html
      lang="en"
      className={`dark ${GeistSans.variable} ${display.variable} ${mono.variable}`}
    >
      <body className="min-h-screen bg-background text-foreground antialiased">
        {children}
        <Toaster position="top-center" />
      </body>
    </html>
  );
}
```

Then point the brand font tokens at those variables in `app/globals.css`, replacing the stack from `tokens.css` line 110 to 112:

```css
--cr-font-display: var(--font-big-shoulders), 'Arial Narrow', system-ui, sans-serif;
--cr-font-mono:    var(--font-ibm-plex-mono), ui-monospace, 'SFMono-Regular', monospace;
--cr-font-body:    var(--font-geist-sans), system-ui, sans-serif;
```

**Deliberate deviation from the brand kit README.** The README says to leave the `@theme inline` block alone. That is correct for colour, and wrong for type: without an entry there, Tailwind's `font-sans` and `font-mono` utilities keep resolving to the framework defaults and a `className="font-mono"` anywhere in the app silently renders in the wrong face. Add three lines to `@theme inline`:

```css
--font-sans:    var(--cr-font-body);
--font-mono:    var(--cr-font-mono);
--font-display: var(--cr-font-display);
```

**Inter never ships.** `round5-meeting-detail.html` and `round5-auth-login-signup.html` declare Inter in their font stacks purely as a stand-in, because they are standalone HTML files that could not reach `next/font`. `round5-dashboard.html` used real Geist and is the correct reference. The two faces are close enough that no specimen in the mockups changes shape when Geist replaces Inter. If you see `Inter` anywhere in shipped code, it is a bug.

### 3. Fix `components/ui/button.jsx` (resolves Open item 2)

Four corrections, all in `buttonVariants`. The current file is the stock `base-nova` button and it violates the brand in four separate places.

| Before (real current code) | After | Why |
|---|---|---|
| `destructive: "bg-destructive/10 text-destructive hover:bg-destructive/20 ... dark:bg-destructive/20 dark:hover:bg-destructive/30"` | `destructive: "border-destructive/45 bg-transparent text-destructive hover:bg-destructive/12 focus-visible:border-destructive/50 focus-visible:ring-destructive/20 dark:hover:bg-destructive/15"` | In this brand the primary action is already red. A red-tinted Delete sitting next to a red-filled Upload reads as the same button. Destructive is differentiated by **shape**, an outline, never by fill or tint. This is what `.btn-danger` does in `round5-dashboard.html` line 359 and in `round5-meeting-detail.html`. |
| `transition-all` (in the base class) | `transition-[background-color,border-color,color,transform,box-shadow] duration-[--cr-dur-hover] ease-[--cr-ease-out]` | Motion rule 4. `all` animates properties you did not intend and pays for layout you did not need. |
| `active:not-aria-[haspopup]:translate-y-px` | `active:not-aria-[haspopup]:scale-[0.97] active:not-aria-[haspopup]:transition-[transform] active:not-aria-[haspopup]:duration-[--cr-dur-press]` | `--cr-press-scale` is 0.97 and applies to every pressable element, no exceptions. A 1px nudge is not the brand's press feedback. |
| `focus-visible:ring-3` | `focus-visible:ring-2` | The focus ring is `--cr-focus-ring`, 2px, and it is the only line in the whole UI heavier than a hairline. A 3px ring is not on the scale. |

Note for the record: the brand kit README states destructive "currently ships a fill". It does not, it ships a 10 percent tint. The correction is still required, for the same reason, and the outline is still the answer.

### 7. Reconcile the icon family

The design specifies a 24-grid family at `--cr-stroke-icon` (1.75px), butt caps, miter joins, shipped in `assets/icons.svg`. The app currently uses `lucide-react`, which is 24-grid at 2px with round caps and round joins.

Do not swap the library. Set the stroke properties globally instead, which is one rule and keeps `lucide-react` and its tree-shaking:

```css
/* The brand's icon line is 1.75px with butt caps and miter joins. Icons are
   content, not chrome, so they sit above the 1px border scale on purpose:
   the frame should recede, the mark should not. */
.lucide {
  stroke-width: var(--cr-stroke-icon);
  stroke-linecap: butt;
  stroke-linejoin: miter;
}
```

Use `assets/icons.svg` only for the marks lucide has no equivalent for.

### 1. Landing (days 4 to 6) · marketing weight

**Reference:** `/private/tmp/claude-501/-Volumes-Crucial-X9-meeting-transcriber/8ad7e38a-12ca-4420-a70e-386689505ce0/scratchpad/moodforge/content/round2-court-reporter-preview.html`, screen 1. This is the approved landing design. It has no Round 5 production file of its own because it doubled as the Round 2 validation screen, so treat the Round 2 file as production-grade for this screen and apply the Round 3b border correction (the 2px stamp border there becomes 1px) and the WCAG corrections (the CTA fill becomes `--cr-red-fill`, the stamp text becomes `--cr-red-fill`, the EXHIBIT labels become `--cr-red-text`, the footer text becomes `--cr-text-muted`).

**This route does not exist.** `app/page.js` currently calls `verifySession()`, which redirects to `/login` when signed out, so there is no public front door at all. Build it carefully, because this changes the auth shape of the app's root route:

```js
// app/page.js
import { getSessionUserId } from '@/app/lib/session';
import Landing from './Landing';
import DashboardPage from './DashboardPage';

// `/` is the one route that serves two surfaces. Signed out it is the public
// marketing page and touches no user data at all. Signed in it is the
// dashboard, and that branch still goes through verifySession() inside
// DashboardPage, so the auth boundary is unchanged: nothing reads a meeting
// without it. getSessionUserId() here is only deciding which surface to
// render, never authorising a read.
export default async function Root() {
  const userId = await getSessionUserId();
  if (!userId) return <Landing />;
  return <DashboardPage />;
}
```

# ▼ MOTION APPENDIX ▼ (verbatim, do not modify)

> **Read this before writing any animation code. Load the `emil-design-eng` skill before touching motion. Change an easing or a duration without consulting it and you are breaking the brand.**

## The three easing tokens (already in tokens.css)

```css
--cr-ease-out:    cubic-bezier(0.23, 1, 0.32, 1);   /* GSAP power3.out   */
--cr-ease-in-out: cubic-bezier(0.77, 0, 0.175, 1);  /* GSAP power4.inOut */
--cr-ease-drawer: cubic-bezier(0.32, 0.72, 0, 1);   /* GSAP power2.out   */
```

Entering or exiting: `--cr-ease-out`. Moving or morphing on screen: `--cr-ease-in-out`. Sheets and drawers: `--cr-ease-drawer`. **There is no fourth.**

**Hover and colour change:** plain `ease`. **Marquees, progress bars, constant motion:** `linear`.

**Never change these three values.** They are the entire motion vocabulary of the product. Adding a fourth curve, or nudging one of these, is a design decision that needs review, not a one-line commit.

## The duration scale (already in tokens.css)

| Token | ms | Applies to | Surface |
|---|---|---|---|
| `--cr-dur-press` | 140 | `scale(0.97)` on `:active`, toggle knob | both |
| `--cr-dur-hover` | 160 | background, colour, border change | both |
| `--cr-dur-tooltip` | 160 | tooltips, small popovers | both |
| `--cr-dur-dropdown` | 200 | dropdown menu, select, avatar menu | both |
| `--cr-dur-drawer` | 320 | drawers and sheets | both |
| `--cr-dur-modal` | 400 | dialogs. **The product ceiling.** | both |
| `--cr-dur-reveal` | 600 | `ScrollTrigger.batch` entrance | marketing |
| `--cr-dur-hero` | 700 | landing hero timeline step | marketing |

## The stagger and press values

| Token | Value | Applies to |
|---|---|---|
| `--cr-stagger-row` | 50ms | app list rows. Fast, this is a tool |
| `--cr-stagger-reveal` | 120ms | landing panels |
| `--cr-stagger-line` | 120ms | transcript lines typing on |
| `--cr-stagger-char` | 25ms | landing hero per-character stagger. **Derived**, `--cr-stagger-row / 2`, not a first-class token. Half a row stagger keeps a full headline under the 800ms the display type wants. Promote it only if a second thing uses it |
| `--cr-press-scale` | 0.97 | every pressable element, **no exceptions** |

## The ten hard rules, verbatim

1. **Never animate a keyboard-initiated action.** Escape, Enter, Cmd+K, arrow keys. Those fire hundreds of times a day and animation makes them feel broken.
2. **Never use `ease-in` on UI.** It delays the first movement, which is the exact frame the user is watching hardest, so a 200ms `ease-in` feels slower than a 200ms `ease-out`.
3. **Never animate from `scale(0)`.** Start at 0.95 or higher, combined with opacity. Nothing in the real world appears from nothing.
4. **Never use `transition: all`.** Name the properties. `all` animates things you did not intend and pays for layout you did not need.
5. **Only animate `transform` and `opacity`.** Width, height, margin and padding trigger layout on every frame.
6. **Popovers scale from their trigger** (`transform-origin: var(--transform-origin)`). Modals are the one exception and stay centred, because they are not anchored to a trigger.
7. **Exits are faster than entrances.** The user has already decided. Do not make them wait for the system to agree. Exit at roughly 75 percent of the entrance duration.
8. **Transitions, not keyframes,** for anything that can be re-triggered mid-flight. Keyframes restart from zero, transitions retarget from their current value.
9. **Gate hover animations** behind `@media (hover: hover) and (pointer: fine)`. Touch devices fire hover on tap.
10. **Reduced motion means fewer and gentler, not none.** Keep opacity and colour transitions, which aid comprehension. Remove travel, scale, and the ribbon draw.

## The four-question framework, answered for this product

Asked in this order, every time, before a single line of animation code exists.

**Question 1. Should this animate at all?**

| How often | In this app | Verdict |
|---|---|---|
| 100+ per day | Enter in the search box, Escape out of a dialog, arrow keys through rows, the polling refresh every 4s | None. Ever |
| Tens per day | Row hover, avatar menu, the speaker-rename input opening, tag chips | Hover and press only |
| Occasional | Upload dialog, merge-speakers dialog, webhook settings drawer, a completion toast | Standard, under 400ms |
| Rare or first time | The signed-out landing page, the empty dashboard, the hand-off ribbon | Delight allowed |

The dashboard re-renders every 4 seconds while a meeting is transcribing. Anything that animated on data arrival would flicker forever. It does not animate.

**Question 2. Why does this animate?** One of exactly four reasons.

- **Spatial consistency.** The webhook settings drawer leaves through the same edge it entered, so the drag handle reads as "pull me back down" without a label.
- **State indication.** A meeting row moving from Transcribing to Complete crossfades its status pill. The colour carries the news, the motion says the news just arrived.
- **Feedback.** Upload presses to 0.97. The file has not left the browser yet, but the interface has already confirmed it heard you.
- **Preventing a jarring change.** A delivery toast that appeared instantly at the corner reads as a rendering bug. Eight pixels of travel is the difference between a glitch and a notice.

No fifth reason exists. "It looks nice" is not on the list.

**Question 3. What easing?** From the table above.

**Question 4. How fast?** From the duration scale above. Press 140, hover 160, tooltip 160, dropdown 200, drawer 320, modal 400, reveal 600, hero 700.

## Two documented exceptions, both deliberate

1. **The focus ring animates `outline-offset`**, which is not `transform` or `opacity`. It is legal because `outline` does not participate in layout, so no frame pays for it. This is the only property outside transform and opacity that any UI element in this system animates.
2. **Escape and other keydown-triggered overlay closes use a forced 0ms duration**, never the token. This is rule 1 enforced in code rather than trusted to discipline. `data-instant="true"` on the scrim sets `transition-duration: 0ms`, as in `round5-dashboard.html` line 553.

## The SVG transform gotcha (a real bug, found and fixed during the brand kit build)

**Tweening `x` or `y` on an SVG `<g>` that already carries a `transform` attribute snaps the element to the wrong position.** GSAP parses the existing `transform="translate(58,196)"` as its own starting baseline, so a tween from `x: -20` resolves against 58 rather than against 0, and the element jumps.

The fix is structural and is already baked into `docs/design/brand-kit/assets/handoff-ribbon.svg`: **every animatable group is a plain, untransformed wrapper `<g>` around the positioned `<g>`.** Animate the wrapper, never the inner group.

```html
<!-- Correct. The outer <g> is the GSAP target and carries no transform. -->
<g class="cr-hand-a"><g fill="var(--cr-paper, #F4F1EA)" transform="translate(58,196)">
  <rect x="6" y="30" width="70" height="46" rx="23"/>
  ...
</g></g>
```

```js
// Correct: targets the untransformed wrapper.
gsap.from('.cr-hand-a', { x: -20, opacity: 0, duration: 0.6, ease: 'power3.out' });

// Wrong: targets a group with transform="translate(58,196)" and snaps.
gsap.from('.cr-hand-a > g', { x: -20, opacity: 0 });
```

**When `HandoffRibbon.jsx` is built, keep the wrapper groups.** They look redundant in JSX and they are not. Deleting one reintroduces this bug silently, and it only shows on the first frame of the animation, which is the frame nobody screenshots. The same applies to `.cr-hand-b`, `.cr-cargo-in` and `.cr-cargo-out`.

## React cleanup, the required pattern

Always `useGSAP()` with a `scope`. The scope is what stops a selector like `.row` from reaching rows in a different component, and it is what makes cleanup automatic.

```js
'use client';

import { useRef } from 'react';
import gsap from 'gsap';
import { useGSAP } from '@gsap/react';
import { ScrollTrigger } from 'gsap/ScrollTrigger';

gsap.registerPlugin(useGSAP, ScrollTrigger);

export default function LandingHero() {
  const root = useRef(null);

  useGSAP(() => {
    // Reduced motion is read here, not in CSS, because GSAP writes inline
    // styles that a media query cannot override. Travel flattens to 0, the
    // sequence and the opacity survive.
    const reduce = window.matchMedia('(prefers-reduced-motion: reduce)').matches;
    const y = reduce ? 0 : 18;

    gsap.timeline({ defaults: { ease: 'power3.out', duration: reduce ? 0.2 : 0.7 } })
      .from('.cr-eyebrow',   { y, opacity: 0 })
      .from('.cr-hero-char', { y, opacity: 0, stagger: reduce ? 0 : 0.025 }, '-=0.45')
      .from('.cr-lede',      { y, opacity: 0 }, '-=0.45')
      .from('.cr-cta-row',   { y, opacity: 0 }, '-=0.40')
      .from('.cr-transcript-card', { y, opacity: 0, duration: reduce ? 0.2 : 0.8 }, '-=0.55');
  }, { scope: root });

  return <section ref={root}>{/* ... */}</section>;
}
```

If `useGSAP` is not an option for some reason, the fallback is `gsap.context()` inside `useEffect` with a **mandatory** `ctx.revert()` in the cleanup:

```js
useEffect(() => {
  const ctx = gsap.context(() => {
    gsap.from('.cr-row', { y: 6, opacity: 0, duration: 0.2, stagger: 0.05 });
  }, rootRef);
  return () => ctx.revert();
}, []);
```

Never create a GSAP animation inside an event handler registered in `useGSAP` without wrapping the handler in `contextSafe`. Handlers run after the hook has executed, so anything they create is outside the context and never gets reverted.

## `ScrollTrigger.batch` for the landing reveals

```js
useGSAP(() => {
  const reduce = window.matchMedia('(prefers-reduced-motion: reduce)').matches;
  gsap.set('.cr-reveal', { y: reduce ? 0 : 20, autoAlpha: 0 });

  ScrollTrigger.batch('.cr-reveal', {
    start: 'top 88%',
    once: true,
    onEnter: (batch) => gsap.to(batch, {
      autoAlpha: 1,
      y: 0,
      duration: reduce ? 0.2 : 0.6,
      ease: 'power3.out',
      stagger: reduce ? 0 : 0.06
    })
  });

  // Both brand faces are webfonts and Big Shoulders is condensed, so the page
  // reflows measurably once they land. ScrollTrigger measured its start
  // positions against the fallback metrics, so it has to re-measure or the
  // triggers sit in the wrong place on a cold load.
  document.fonts?.ready.then(() => ScrollTrigger.refresh());
}, { scope: root });
```

**Ship the reveal safety net with it.** A reveal is an enhancement, and an enhancement is never allowed to be the reason content is unreadable. Anything still at zero opacity while it is on screen gets shown, no animation, no questions. The implementation is in `round4-animations.html`, section 12, `revealSafety()`.

## The landing to dashboard page transition

Exit at 75 percent of the entrance duration, on `--cr-ease-in-out`, with `opacity`, a 2 percent scale down, and 2px of blur. The blur exists for one reason: without it a crossfade shows two separate readable screens stacked on each other for a fifth of a second and reads as a rendering fault. Two pixels of blur makes the eye accept it as one object changing. Keep blur under 20px, it is expensive in Safari.

The dashboard then enters at 400ms with rows staggered at `--cr-stagger-row` (50ms), which is the entire animation budget the product side gets. Going back out is faster still.

## Performance rules

- Animate `transform` and `opacity` only. `x`, `y`, `scale`, `rotation` and `opacity` stay on the compositor. `width`, `height`, `top`, `left`, `margin`, `padding` trigger layout every frame. The Dashboard progress bar is the worked example: it animates `scaleX`, not `width`.
- Put `will-change: transform` in CSS only on elements that actually animate, and remove it when the animation is done. Not "just in case", it costs a layer per element.
- Use `stagger` rather than many tweens with manual delays. One tween, one timeline, less work.
- Use `gsap.quickTo()` for anything updated per pointer move. It reuses a single tween instead of allocating one per event.
- Batch `ScrollTrigger` instances with `ScrollTrigger.batch()` rather than creating one per element.
- Call `ScrollTrigger.refresh()` only when layout actually changed (fonts loaded, content injected), debounced. Not on every resize tick.
- Never update a CSS custom property on a parent to drive a child's transform. Custom properties inherit, so changing one recalculates styles for every descendant. Write `element.style.transform` directly.
- GSAP is loaded on marketing routes only. Do not import it into `app/Dashboard.js` or `MeetingDetail.js`, both of which are already the heaviest client bundles in the app.

## shadcn house rules that apply to every file this spec touches

- `className` is for layout, never for colour or typography. If a component needs a different colour, the token is wrong, not the component.
- No `space-x-*` or `space-y-*`. Use `flex` with `gap-*`, and `flex flex-col gap-*` for vertical stacks.
- `size-*` when width and height match. `size-8`, not `w-8 h-8`.
- `truncate`, not `overflow-hidden text-ellipsis whitespace-nowrap`.
- No manual `dark:` colour overrides. The app is always dark, semantic tokens already resolve correctly.
- `cn()` for conditional classes, not template-literal ternaries. `app/Dashboard.js` line 456 currently uses a template literal for the dropzone drag state. Convert it.
- No manual `z-index` on overlay components. Dialog, Popover and friends manage their own stacking.
- Icons inside `Button` use `data-icon="inline-start"` or `data-icon="inline-end"` and carry **no sizing class**. The component sizes them.

## Open item 5 in full: the product name

The wordmark reads `MEETING.TXT`. That is a placeholder carried from the Round 2 mockup and it is **not a proposed name**. Do not invent one, and do not let the placeholder quietly become the name by shipping it and forgetting.

The three wordmark SVGs use live `<text>` rather than outlined paths specifically so that swapping the name is editing one string per file. `assets/mark-icon.svg` carries no letterforms and survives the naming decision untouched. `components/brand/Wordmark.jsx` should hold the name in one exported constant so the swap is one line in one file.

Ship Phases 1 to 3 with the placeholder. Track the name as a release blocker for the marketing surfaces only. The product surfaces reference the mark, not the wordmark, and are unaffected.

## Open item 8 in full: why the border scale has exactly one tier

**Blink floors sub-pixel border widths.** `border: 1.5px` computes and paints as `1px` in Chrome at any `devicePixelRatio`, while Safari and Firefox honour it. Verified directly during the brand kit build: a probe element with `border-top: 1.5px` reports `borderTopWidth: "1px"` at both DPR 1 and DPR 2, while `2px` reports `2px`.

A tier that exists in two of three engines is not a tier, it is an inconsistency. So the entire border scale is `--cr-stroke-hair: 1px`, and emphasis is carried by the rule's **colour**: `--cr-rule-soft` for dividers and card borders, `--cr-rule-strong` for input borders and chip outlines, `--cr-paper` for the hero block's structural edges, `--cr-red` for section openers and accent left-borders. That is the heaviest thing this system says, said at 1px.

Version 1 of the kit shipped a 2px and a 2.5px tier and the system read as a stack of thick bordered boxes. The user rejected it in Round 3 ("no thick borders please"). A 1.5px middle tier was tried as the replacement and removed for the Chrome reason above.

**Do not add the heavier tokens back.** If a box seems to need more weight than a hairline, it does not need a heavier border. It needs a different background, or more space.

Three line weights exist that are **not borders** and are not on the scale. Do not reach for them to draw a box.

| Token | Value | Why it is exempt |
|---|---|---|
| `--cr-focus-ring` | 2px | Accessibility affordance, and now the only line in the UI heavier than a hairline, which is exactly what a focus indicator should be. Never trade this down for aesthetics |
| `--cr-stroke-icon` | 1.75px | The icon family's drawn line, fixed at every rendered size. Icons are content, so they sit above the chrome scale on purpose: the frame should recede, the mark should not |
| `--cr-stroke-ribbon` | 34px | The hand-off ribbon's artwork line weight. Illustration, not chrome. Locked |

## Rollback

Every phase is independently revertable, which is why the commit boundaries matter.

1. **Phase 1 rollback:** `git revert` the tokens commit. `app/globals.css` returns to the stock nova theme and every screen still renders, just in the old palette, because nothing outside that file hard-codes a colour. The font commit and the `button.jsx` commit revert independently of it.
2. **Phase 2 rollback:** each screen is its own commit and its own file. Reverting the Dashboard does not touch MeetingDetail. The Landing revert is the only one that also touches `app/page.js`, so revert it as a pair with `app/DashboardPage.js`.
3. **Phase 3 rollback:** motion is additive. Reverting it leaves the screens correct and static.
4. **Column measure rollback:** its own commit, by requirement. One revert.
